## 1. 프로젝트 개요

이 프로젝트는 Python의 기본 문법과 객체지향 프로그래밍, JSON 파일 입출력, 예외 처리, Git 작업 흐름을 학습하기 위해 제작했습니다.

개별 문제는 `Quiz` 객체로 표현하고, 메뉴와 게임 진행 및 데이터 관리는 `QuizGame`이 담당하도록 역할을 분리했습니다. 프로그램을 종료한 뒤 다시 실행해도 등록한 퀴즈와 점수 기록이 유지됩니다.

## 2. 퀴즈 주제와 선정 이유

퀴즈 주제는 **대한민국의 주요 국경일과 기념일**입니다.

현충일, 제헌절, 개천절, 한글날, 삼일절은 익숙한 기념일이지만 정확한 날짜를 혼동하기 쉽습니다. 정답이 명확하고 문제와 선택지를 구성하기 쉬워 4지선다 퀴즈의 기본 주제로 선정했습니다.

기본 퀴즈는 `default_quizzes.py`에 5개가 등록되어 있으며, 프로그램에서 새로운 퀴즈를 추가하거나 기존 퀴즈를 삭제할 수 있습니다.

## 3. 실행 환경

- Python 3.10 이상
- 외부 라이브러리 사용 없음
- 사용한 표준 라이브러리
  - `json`: JSON 파일 저장 및 불러오기
  - `pathlib`: `state.json` 경로 생성
  - `random`: 퀴즈 순서 무작위 배치
  - `datetime`: 플레이 날짜와 시간 기록



프로그램을 실행하면 다음 메뉴가 출력됩니다.

```text
1. 퀴즈 풀기

5. 퀴즈 삭제
6. 점수 기록

```

## 5. 기능 목록

### 퀴즈 풀기

- 풀 문제 수 선택
- 문제 순서 무작위 배치
- 4지선다 정답 입력
- 정답과 오답 결과 출력
- 문제별 힌트 사용
- 점수 계산 및 최고 점수 갱신
- 플레이 기록 저장

### 퀴즈 추가

문제, 선택지 4개, 정답 번호와 힌트를 입력하여 새로운 퀴즈를 등록합니다. 추가된 퀴즈는 즉시 `state.json`에 저장됩니다.

### 퀴즈 목록

현재 등록된 퀴즈의 번호와 문제 내용을 확인할 수 있습니다.

### 퀴즈 삭제

목록에서 삭제할 퀴즈 번호를 입력한 뒤 `y/n`으로 삭제 여부를 확인합니다. 삭제 결과는 즉시 `state.json`에 반영됩니다.

### 최고 점수와 점수 기록

플레이 결과를 기존 최고 점수와 비교하여 더 높은 경우 갱신합니다.

모든 게임이 끝날 때마다 다음 정보를 기록합니다.

- 플레이 날짜와 시간
- 푼 문제 수
- 최종 점수

아직 퀴즈를 풀지 않았다면 플레이 기록이 없다는 안내 메시지를 출력합니다.

## 6. 점수 계산

기본 점수는 정답 비율을 100점 만점으로 계산합니다.

```text
기본 점수 = int(100 × 정답 수 / 푼 문제 수)
힌트 감점 = 힌트 사용 횟수 × 10
최종 점수 = max(0, 기본 점수 - 힌트 감점)
```

힌트는 한 문제당 한 번 선택할 수 있으며, 사용할 때마다 10점이 차감됩니다. 감점 결과가 음수가 되면 최종 점수는 0점으로 처리합니다.

## 8. 클래스 역할

### `Quiz`

하나의 퀴즈를 표현합니다.

- 속성: `question`, `choices`, `answer`, `hint`
- 문제와 선택지 출력
- 힌트 출력
- 사용자 정답 확인
- 문제, 선택지, 정답과 힌트의 유효성 검증
- `to_dict()`로 객체를 딕셔너리로 변환
- `from_dict()`로 딕셔너리를 객체로 변환

### `QuizGame`

게임 전체의 실행 상태를 관리합니다.

- 속성: `quizzes`, `best_score`, `score_history`
- 메뉴 출력과 기능 선택
- 퀴즈 풀기, 추가, 목록 조회와 삭제
- 문제 수 선택과 랜덤 출제
- 힌트 감점과 점수 계산
- 최고 점수와 전체 플레이 기록 관리
- `state.json` 저장 및 불러오기

객체와 딕셔너리 사이의 변환은 `Quiz`가 담당하고, `QuizGame`은 변환된 데이터를 모아 저장하거나 다시 불러옵니다.

## 9. 데이터 파일 설명

`state.json`은 프로젝트 루트에 UTF-8로 저장됩니다.

```json
{
    "quizzes": [
        {
            "question": "현충일의 날짜로 알맞은 것은?",
            "choices": [
                "6월 5일",
                "6월 6일",
                "6월 7일",
                "6월 8일"
            ],
            "answer": 2,
            "hint": "6"
        }
    ],
    "best_score": 90,
    "score_history": [
        {
            "played_at": "2026-08-15T21:12:01",
            "question_count": 5,
            "score": 90
        }
    ]
}
```

| 필드 | 설명 |
| --- | --- |
| `quizzes` | 저장된 퀴즈 목록 |
| `question` | 문제 내용 |
| `choices` | 4개의 선택지 |
| `answer` | 1부터 4까지의 정답 번호 |
| `hint` | 문제의 힌트 |
| `best_score` | 최고 점수이며, 플레이 기록이 없으면 `null` |
| `score_history` | 완료된 전체 게임 기록 |
| `played_at` | 게임을 완료한 날짜와 시간 |
| `question_count` | 해당 게임에서 푼 문제 수 |
| `score` | 힌트 감점을 반영한 최종 점수 |

파일이 없으면 기본 퀴즈로 시작합니다. JSON 문법이 손상되거나 내부 데이터가 올바르지 않으면 예외를 처리하고 기본 퀴즈를 사용합니다.

## 10. 입력 및 예외 처리

숫자를 입력하는 메뉴, 문제 수, 정답 번호와 삭제 번호에서 다음 경우를 처리합니다.

- 입력값 앞뒤 공백 제거
- 빈 값 입력
- 숫자가 아닌 값 입력
- 허용 범위를 벗어난 숫자 입력

`y/n` 입력이 필요한 곳에서는 다른 값을 입력하면 다시 입력받습니다.

프로그램 실행 중 `Ctrl+C` 또는 입력 스트림 종료가 발생하면 현재 상태를 저장한 뒤 안내 메시지를 출력하고 종료합니다.

## 11. 트러블슈팅

### 미플레이 상태와 실제 0점을 구분하지 못한 문제

**문제**

최고 점수의 초기값이 `0`이면 아직 퀴즈를 풀지 않은 상태와 실제로 플레이해서 0점을 받은 상태를 구분할 수 없었습니다.

**원인**

서로 다른 두 상태를 같은 정수 `0`으로 표현했기 때문입니다.

**해결**

최고 점수의 초기값을 `None`으로 변경했습니다. 최초 플레이 결과는 다음 조건으로 처리하여 0점도 정상적으로 저장되도록 했습니다.

```python
self.best_score is None or score > self.best_score
```

점수 조회 시 `None`이면 플레이 기록이 없다는 메시지를 출력하고, 실제 0점은 최고 점수 0점으로 출력하도록 구분했습니다.

### JSON 형식은 정상이지만 내부 값이 잘못된 문제

**문제**

JSON 문법이 정상이라도 선택지가 4개가 아니거나 정답이 1~4 범위를 벗어나면 게임이 올바르게 동작하지 않을 수 있었습니다.

**원인**

기존 코드는 JSON 문법 오류와 필수 키 누락은 처리했지만, 각 퀴즈의 실제 값까지 검증하지 않았습니다.

**해결**

`Quiz.__init__()`에서 문제와 힌트가 빈 문자열인지, 선택지가 정확히 4개인지, 정답이 1~4 사이의 정수인지 검사하도록 수정했습니다.

또한 `Quiz`에 `to_dict()`와 `from_dict()`를 추가하여 개별 퀴즈의 검증과 변환 책임을 `Quiz` 클래스에 두었습니다. 잘못된 데이터가 들어오면 `ValueError`가 발생하고 `load_state()`의 예외 처리에서 기본 퀴즈를 사용합니다.

## 12. Git 작업 기록

퀴즈 풀기 기능은 `feature/play-quiz` 브랜치에서 구현한 뒤 `main` 브랜치로 병합했습니다. 이후 기능별로 변경 내용을 나누어 커밋했습니다.

전체 브랜치와 커밋 기록은 다음 명령으로 확인할 수 있습니다.

```bash
git log --oneline --graph --all
```

개발 완료 후 저장소를 별도 디렉터리에 `clone`하고, 복제된 저장소에서 변경사항을 `commit`과 `push`한 뒤 기존 작업 디렉터리에서 `pull`하여 반영 여부를 확인합니다.
